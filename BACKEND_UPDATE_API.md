# CAISSE212 — Backend Update System — Implementation Guide

This document describes exactly what the backend needs to implement to support
the desktop auto-update feature used by the CAISSE212 POS app.

---

## How it works (overview)

```
[Dev machine]                    [Server]                      [POS App]
     │                               │                              │
     │  1. flutter build windows     │                              │
     │  2. dart run desktop_updater  │                              │
     │     :release windows          │                              │
     │  3. dart run desktop_updater  │                              │
     │     :archive windows          │                              │
     │  → generates dist/ folder     │                              │
     │                               │                              │
     │  4. ZIP the dist folder        │                              │
     │  5. POST /api/pos/upload-update│                              │
     │     (zip + metadata)  ──────► │ extracts zip               │
     │                               │ saves files to disk         │
     │                               │ updates app-archive.json    │
     │                               │                              │
     │                               │ ◄── GET /api/pos/app-archive.json
     │                               │                              │
     │                               │ ──► returns JSON manifest   │
     │                               │                              │
     │                               │ ◄── GET /updates/1.0.1+2-windows/hashes.json
     │                               │ ◄── GET /updates/1.0.1+2-windows/posecrea.exe
     │                               │ ◄── GET /updates/1.0.1+2-windows/...
     │                               │                              │
     │                               │ ──► serves static files ───► app updates itself
```

## What the backend needs to implement

### 1. Upload endpoint — `POST /api/pos/upload-update`

This is called by the developer (you) after building a new version.
It receives a ZIP of the `dist/` folder, extracts it, and updates the manifest.

#### Request

- **Method:** `POST`
- **URL:** `/api/pos/upload-update`
- **Auth:** Admin JWT (not POS token — this is a developer/admin action)
- **Content-Type:** `multipart/form-data`

| Field | Type | Required | Description |
|---|---|---|---|
| `file` | File (ZIP) | ✅ | The ZIP of the dist folder (see what to zip below) |
| `version` | String | ✅ | e.g. `"1.0.1"` |
| `shortVersion` | Integer | ✅ | Build number, e.g. `2`. Must be higher than previous |
| `platform` | String | ✅ | `"windows"` / `"linux"` / `"macos"` |
| `mandatory` | Boolean | ❌ | Default `false`. If `true`, POS cannot skip update |
| `changes` | String (JSON array) | ❌ | e.g. `[{"type":"fix","message":"Bug fixes"}]` |
| `date` | String | ❌ | `"YYYY-MM-DD"`. Defaults to today |

#### What the ZIP must contain

The developer ZIPs the contents of the generated `dist/<buildNumber>/<version>+<build>-<platform>/` folder.

Example — for Windows build number 2, version 1.0.1:
```
# Folder generated by CLI:
dist/2/1.0.1+2-windows/
  hashes.json
  posecrea.exe
  flutter_windows.dll
  data/
    flutter_assets/
    ...

# Developer ZIPs the CONTENTS of that folder:
zip -r update-windows.zip dist/2/1.0.1+2-windows/.
# Result: update-windows.zip contains hashes.json at root, posecrea.exe at root, etc.
```

> ⚠️ The ZIP must contain the files **at the root level**, not inside a subfolder.
> So `hashes.json` should be at the ZIP root, not at `1.0.1+2-windows/hashes.json`.

#### What the server must do when it receives the upload

1. **Validate** the ZIP and form fields
2. **Create** the destination folder on disk:
   ```
   <static-files-root>/updates/<version>+<shortVersion>-<platform>/
   ```
   Example:
   ```
   /var/caisse212/static/updates/1.0.1+2-windows/
   ```
3. **Extract** the ZIP contents into that folder
4. **Verify** that `hashes.json` exists in the extracted folder (it must be there)
5. **Update** the `app-archive.json` manifest in DB or on disk (see format below)
6. **Return** success response

#### Success response `200 OK`

```json
{
  "success": true,
  "message": "Update 1.0.1+2 for windows uploaded successfully",
  "url": "https://app.caisse212.com/updates/1.0.1+2-windows"
}
```

#### Error responses

| Status | Meaning |
|---|---|
| `400` | Missing fields, invalid platform, shortVersion not incremented |
| `401` | Not authenticated as admin |
| `409` | This shortVersion already exists for this platform |
| `500` | ZIP extraction failed |

### 2. Manifest endpoint — `GET /api/pos/app-archive.json`

This is called automatically by every POS app on startup to check if an update exists.

- **Method:** `GET`
- **URL:** `/api/pos/app-archive.json`
- **Auth:** POS Bearer token (standard `Authorization: Bearer <token>` + `X-POS-Name` header)
- **Content-Type response:** `application/json`

#### Response format — EXACT structure required by the `desktop_updater` package

```json
{
  "appName": "CAISSE212",
  "description": "POS Terminal Updates",
  "items": [
    {
      "version": "1.0.1",
      "shortVersion": 2,
      "changes": [
        { "type": "fix",  "message": "Fix ticket encoding in French mode" },
        { "type": "feat", "message": "Desktop auto-updater added" }
      ],
      "date": "2026-04-22",
      "mandatory": false,
      "url": "https://app.caisse212.com/updates/1.0.1+2-windows",
      "platform": "windows"
    },
    {
      "version": "1.0.1",
      "shortVersion": 2,
      "changes": [
        { "type": "fix", "message": "Fix ticket encoding in French mode" }
      ],
      "date": "2026-04-22",
      "mandatory": false,
      "url": "https://app.caisse212.com/updates/1.0.1+2-linux",
      "platform": "linux"
    }
  ]
}
```

#### Field rules — IMPORTANT

| Field | Type | Rules |
|---|---|---|
| `appName` | String | **MUST NOT be null** — causes app crash if null |
| `description` | String | **MUST NOT be null** — causes app crash if null |
| `items` | Array | All versions for all platforms go here |
| `version` | String | Human-readable e.g. `"1.0.1"` |
| `shortVersion` | Integer | **Must be greater than installed** for update to trigger |
| `changes` | Array | Can be empty `[]` but must be present |
| `changes[].type` | String | Optional. One of: `feat`, `fix`, `chore`, `docs`, `style` |
| `changes[].message` | String | Required per change item |
| `date` | String | `"YYYY-MM-DD"` format |
| `mandatory` | Boolean | `true` = user cannot skip |
| `url` | String | Full URL to the extracted folder — **NO trailing slash** |
| `platform` | String | Exactly `"windows"`, `"linux"`, or `"macos"` |

> ⚠️ The `url` field must point to the **folder**, not a zip file.
> The POS app will append `/hashes.json` and individual file paths to this URL.
> Example: `url` = `"https://app.caisse212.com/updates/1.0.1+2-windows"`
> App will fetch: `https://app.caisse212.com/updates/1.0.1+2-windows/hashes.json`
> Then: `https://app.caisse212.com/updates/1.0.1+2-windows/posecrea.exe` etc.

#### Keep all versions or only the latest?

Keep **only the latest version per platform** in `items`. The app only needs to know
the current latest — it does not need history. Each upload replaces the previous
entry for that platform.

### 3. Static file serving — `GET /updates/**`

The extracted update folder files must be publicly accessible via HTTP.

- **Method:** `GET`
- **URL pattern:** `/updates/<version>+<build>-<platform>/<filename>`
- **Auth:** None — these must be publicly accessible (the `desktop_updater` package
  fetches them directly using `http` with no auth headers)
- **Example URLs that must work:**
  ```
  GET /updates/1.0.1+2-windows/hashes.json       → 200 OK (JSON file)
  GET /updates/1.0.1+2-windows/posecrea.exe       → 200 OK (binary)
  GET /updates/1.0.1+2-windows/flutter_windows.dll → 200 OK (binary)
  GET /updates/1.0.1+2-windows/data/flutter_assets/version.json → 200 OK
  ```

#### Spring Boot — how to serve the extracted folder as static files

Option A — serve from `resources/static` (requires redeployment, not recommended):
```
src/main/resources/static/updates/1.0.1+2-windows/...
```

Option B — serve from an external directory on disk (recommended):
```java
@Configuration
public class StaticResourceConfig implements WebMvcConfigurer {

    @Value("${app.updates.path:/var/caisse212/static/updates}")
    private String updatesPath;

    @Override
    public void addResourceHandlers(ResourceHandlerRegistry registry) {
        registry
            .addResourceHandler("/updates/**")
            .addResourceLocations("file:" + updatesPath + "/")
            .setCacheControl(CacheControl.maxAge(1, TimeUnit.HOURS));
    }
}
```

Set in `application.properties`:
```properties
app.updates.path=/var/caisse212/static/updates
```

### 4. DB schema suggestion (optional but recommended)

Instead of editing a JSON file on disk each time, store the manifest in the DB:

```sql
CREATE TABLE app_updates (
    id          BIGINT PRIMARY KEY AUTO_INCREMENT,
    platform    VARCHAR(20)  NOT NULL,          -- 'windows', 'linux', 'macos'
    version     VARCHAR(50)  NOT NULL,
    short_version INT        NOT NULL,
    url         VARCHAR(500) NOT NULL,
    changes     TEXT,                           -- JSON array string
    release_date DATE        NOT NULL,
    mandatory   BOOLEAN      DEFAULT FALSE,
    created_at  TIMESTAMP    DEFAULT NOW(),
    UNIQUE KEY uq_platform_short (platform, short_version)
);
```

The `GET /api/pos/app-archive.json` endpoint queries:
```sql
SELECT * FROM app_updates
WHERE (platform, short_version) IN (
    SELECT platform, MAX(short_version)
    FROM app_updates
    GROUP BY platform
)
ORDER BY platform;
```

And maps the result to the JSON format above.

| Method | URL | Auth | Description |
|---|---|---|---|

## Full request/response example

### Upload new Windows version

```bash
curl -X POST https://app.caisse212.com/api/pos/upload-update \
  -H "Authorization: Bearer <admin-token>" \
  -F "file=@update-windows.zip" \
  -F "version=1.0.1" \
  -F "shortVersion=2" \
  -F "platform=windows" \
  -F "mandatory=false" \
  -F 'changes=[{"type":"fix","message":"Fix French encoding"},{"type":"feat","message":"Auto-updater"}]' \
  -F "date=2026-04-22"
```

### Response

```json
{
  "success": true,
  "message": "Update 1.0.1+2 for windows uploaded successfully",
  "url": "https://app.caisse212.com/updates/1.0.1+2-windows"
}
```

### What the POS app then receives on startup

```
GET /api/pos/app-archive.json
Authorization: Bearer <pos-token>
X-POS-Name: POS-COUNTER-1
```

```json
{
  "appName": "CAISSE212",
  "description": "POS Terminal Updates",
  "items": [
    {
      "version": "1.0.1",
```
